# Version 0.1 plan review

This report is for maintainers deciding what version 0.1 delivers and what remains. The generator,
license boundaries, installers, and offline evaluation tests are implemented. Live selection and
quality gates have not passed, so the release cannot claim that the descriptions or index route
well across Codex and Claude Code.

## Original goals

| Goal | State | Result |
| --- | --- | --- |
| Inventory and license Google-authored guides | Partial | `corpus.yaml` contains 23 redistributable guides, 8 local-only SWE-book groups, and 4 catalog-only candidates. It is curated, not exhaustive. |
| Clone and pin sources | Done | The source cache fetches manifest revisions and verifies selected files and license evidence against those revisions. |
| Convert source text without editorial rewriting | Partial | Markdown is copied and HTML/XML is converted to Markdown. The pipeline adds metadata, navigation, provenance, and license files. Images are not copied and some relative links are not rewritten. |
| Generate skills and an index | Built, not validated by models | The committed output has 23 generated guides plus `google-guides-index`. Eight SWE-book skills are generated only under `.generated/skills/`. |
| Measure every generated text file | Done | `catalog/tokens.json` and `catalog/tokens.csv` record file, kind, skill, distribution, and `o200k_base` token counts. |
| Install for Codex and Claude Code | Done | Project installs copy manifest-declared redistributable skills. User installs link the committed pack and, with `--include-swe-book`, the local-only pack. |
| Test automatic selection and index value | Harness done; results pending | The corpus includes explicit, smoke, representative, specificity, index A/B, local planning, and quality cases. No run under the current harness has passed the live gates. |
| Review Agent Skills creators and packaging | Done for version 0.1 | `reports/generator-comparison.md` records why the manifest pipeline is the source generator and why plugin packaging is deferred. |
| Define skill routing for development | Done | `AGENTS.md` routes planning, implementation, testing, review, and shipping. The GitHub templates collect change-specific facts. |

## Keep

- Keep the manifest as the policy and generation source of truth.
- Keep committed and local-only outputs separate. The local-only tree stays ignored and untracked.
- Keep source hashes, license evidence, wrapper licenses, token reports, and validation as release
  gates.
- Keep the evaluation cases and runner, but report only results produced by the current harness
  with pinned models and recorded corpus identity.
- Keep the generator comparison. It answers why a bulk manifest pipeline is needed in addition to
  one-skill creator tools.

## Fixed or deleted in this pass

- Replaced `private` with `local-only` where the text referred to the SWE-book distribution class.
- Made repeated user installs replace byte-identical skill copies with links so later generated
  updates are visible. Different content still blocks the install.
- Changed the changelog to say that version 0.1 adds evaluation cases and runners, not completed
  evaluations.
- Deleted `reports/eval-baseline.md`. Its runs used older workspace isolation, status handling,
  scoring, and unpinned models. Keeping a file named “baseline” made invalid results look like a
  release benchmark. Git history retains it if a future investigation needs it.
- Kept ignored raw evaluation files unchanged. They are local data, not release evidence.

## Debt

The release-blocking work is the live cross-agent matrix and the metadata/layout tuning that it
informs. Source coverage, link and image fidelity, catalog-only license work, plugin packaging, and
evaluation-module boundaries are follow-up work. [`TODOS.md`](../TODOS.md) records each item and
its priority.

## Release position

Version 0.1 can be described as an alpha generator, installer, catalog, and evaluation harness. It
must not be described as a validated skill pack or a completed discoverability study. Merge only
when generation, validation, both install paths, package-boundary checks, and the test suite pass
against the final commit. Leave the live model gates open until disposable keys and pinned model
IDs are available.
