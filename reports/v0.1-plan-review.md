# Version 0.1 plan review

This report records what version 0.1 delivers and what remains. The generator, license boundaries,
installers, and evaluation harness are implemented. One explicit-control case passed on Codex,
Claude Code, OpenCode, OpenClaw, and Hermes. In the corrected full-pack smoke run, all 115
client/case pairs reported the expected skill and no process failed. Of those, 69 routes were
trace-proven and exact; 46 used verified self-report proxies. Repeated positive, near-miss, and
broader quality cases remain.

The discarded index had loaded on only two clients and changed no rubric scores. It also consumed
startup metadata and added evaluator branches, so it was removed. OpenClaw had omitted the
oversized inline Go skill; after its source moved into references, Go routed on all five clients.
A retrospective rescore of the focused Go comparison scored 4/4 concepts with and without the
skill on every client, showing no regression and no lift under the revised rubric. The original
run report remains unchanged at 32/40 and includes two negative deltas.

## Keep

- Keep the manifest as the policy and generation source of truth.
- Keep committed and local-only outputs separate. The local-only tree stays ignored and untracked.
- Keep source hashes, license evidence, wrapper licenses, token reports, and validation as release
  gates.
- Keep the evaluation cases and runner, but report only results produced by the current harness
  with recorded models and corpus identity.
- Keep the generator comparison. It answers why a bulk manifest pipeline is needed in addition to
  one-skill creator tools.

## Fixed or deleted in this pass

- Replaced `private` with `local-only` where the text referred to the SWE-book distribution class.
- Made repeated user installs replace byte-identical skill copies with links so later generated
  updates are visible. Different content still blocks the install.
- Changed the changelog to say that version 0.1 adds evaluation cases and runners, not completed
  evaluations.
- Deleted `reports/eval-baseline.md`. Its runs used older workspace isolation, status handling,
  scoring, and unpinned models. Keeping a file named “baseline” made invalid results look like a
  release benchmark. Git history retains it if a future investigation needs it.
- Kept ignored raw evaluation files unchanged. They are local data, not release evidence.
- Added license acceptance before SWE-book generation and installation. Per-user links remain the
  recommended path; explicit project installs create checked links to the ignored generated tree.
- Replaced two tree-hashing implementations with one checked helper.
- Removed tests for unsupported branches and added boundary tests for the remaining install and
  hashing paths. The full test and coverage gates pass.
- Removed the runtime index, its evaluation profiles, stage paths, and tests.
- Added new-repository onboarding and existing-repository migration guides instead of another
  runtime router.
- Moved the Go source body into three references. Its entry file is 23 lines, OpenClaw now includes
  it, and a retrospective rescore of its five-client comparison found no regression.
- Replaced smoke prompts that referred to absent files with self-contained questions. All 115
  corrected runs reported the expected skill; 69 were trace-proven and exact, while 46 used
  verified self-report proxies.

## Debt

Repeated representative specificity and broader quality work remain. Source coverage, link and
image fidelity, and catalog-only license work are also follow-up work. [`TODOS.md`](../TODOS.md)
records them.

`evals.py` and its tests are large, but splitting files alone would not remove behavior. Keep the
current boundary until a change needs one part to vary independently.

## Release position

Version 0.1 can be described as a generator, installer, catalog, and evaluation harness whose
one-pass routing thresholds passed with separate trace and proxy evidence. It is not a completed
discoverability or answer-quality study. Merge only when generation, validation, both install
paths, package-boundary checks, and the test suite pass against the final commit.
