# Version 0.1 plan review

This report records the current release shape, what changed after the first experiments, and what
still needs evidence.

## What is built

| Goal | State | Result |
| --- | --- | --- |
| Inventory and license the sources | Partial | The manifest contains 16 public skills, 8 local SWE-book skills, and 6 catalog-only candidates. It is curated, not exhaustive. |
| Pin and verify sources | Done | Selected source and license files must match exact Git revisions and are recorded with SHA-256 hashes. |
| Produce task-focused skills | Done | Public guides are reviewed recipes. SWE-book skills contain exact selected passages grouped by recurring engineering job. |
| Keep restricted text local | Done | Book output stays under ignored `.generated/skills/`; the installer requires license acceptance and links rather than copies it. |
| Install the pack | Done | User installs support Codex and Claude Code; project installs copy public skills and link book skills. |
| Measure output | Done | The catalog records all artifacts and token counts. Public main files are 888–2,078 tokens; local main files are 4,254–4,733. |
| Test routing and answer quality | Needs a fresh run | The harness supports Codex, Claude Code, OpenCode, OpenClaw, and Hermes, but saved results used the previous skill corpus. |

## What changed and why

- Removed the persistent routing index. It consumed startup context and did not improve the saved
  comparison.
- Removed source bundles that were obsolete, duplicated another skill, or had no clear task.
- Replaced oversized guide dumps and vague progressive disclosure with self-contained skills.
- Reorganized the SWE book by engineering job rather than book chapter:
  teamwork and leadership, developer productivity, engineering standards, code-review systems,
  testing, change management, builds/dependencies/CI, and compute platforms.
- Kept the useful source detail by selecting exact headings and paragraph blocks instead of
  rewriting the book into short summaries.
- Left documentation as one public `google-documentation-guide`; a second organization-level book
  skill did not justify another trigger.
- Made the normal installer offer the complete pack and handle book-license acceptance without a
  separate inclusion flag.

## Evidence carried forward

The earlier five-client runs were useful diagnostics, not evidence for the rewritten pack. They
showed that an oversized Go skill could be omitted, that a routing index had little value, and
that self-report-only traces could not prove exact routing. Because the skill names and bodies
have since changed, their headline rates are retired.

The current release needs bounded forward tests that answer three questions:

1. Does each description select the expected skill without unrelated loads?
2. Does the self-contained body surface the important rules that agents previously missed?
3. Does following the guide improve a task result rather than only make the answer sound more
   complete?

Three fresh-agent qualitative probes checked the new organization. A webhook-testing prompt
surfaced configuration, load, stale-double, hermeticity, flakiness, diagnostic, and ownership
risks. A polyglot-standards prompt combined rule lifecycle, static analysis, review tooling, CI,
and team guidance. A 200-repository API migration prompt combined change management, builds,
testing, productivity, and documentation. The agents found and used the task-based skills without
chapter hints. These probes suggest that the bodies are usable; they are not routing rates or a
quality benchmark.

## Remaining debt

- Run the current five-client smoke and selected quality cases and inspect their trajectories.
- Resolve or keep catalog-only the web sources whose snapshots or licenses are incomplete.
- Decide whether any source diagrams are necessary; the current pack is text-only.
- Keep the full-pack metadata cost under observation. The 24-skill list has little headroom at a
  45-character install root, while selected project installs have more.

## Release rule

Ship only after regenerated output is deterministic, validation passes for public and local
skills, both install paths work, the full test suite passes, and fresh agents can apply the
rewritten skills to representative tasks. Do not present the older model runs as current quality
results.
